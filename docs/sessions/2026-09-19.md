Two bugs in the session's own work were found by using it, which the launch
check could not have caught because both are about where things end up on
screen:

- **`c613c88`, in T-003.** The wave took its normal from the path's *parameter*
  while the position came from its *arc length*. Those are the same point only
  on an evenly parameterised path, which a straight line is, so a wave over a
  line looked right and a wave over a spline lurched. Measured on a test spline,
  the two points were up to 190 units and 100 degrees apart, and the distance
  the entity covered per step varied 54-fold; after the fix, 3-fold.
- **`110fe52`, in T-002.** A spawn-relative state took its offset from the
  entity's position when *that state* began, so every state after the first was
  displaced by wherever the one before it ended. The behaviour now records where
  it started and measures all of its spawn-relative states from there. Only
  visible once every state was drawn, which is the other half of that commit.

`d6965d5` is a feature, not a fix, and it is the one thing on this branch that
was never a task: a path state carries an entry rule, `Snap`, `Linear` or
`Spline`, saying how it travels to its own start. It runs before the state's
duration starts counting, and it also covers the jump from the spawn point into
the first state. The user chose to work it through directly rather than take it
through planning.

## Needs attention

Nothing blocked, and no `NOLINT` was added. Five things are worth knowing:

- **The launch check allows two Vulkan shutdown errors by name**
  (`VUID-vkDestroyBuffer-buffer-00922`, `VUID-vkDestroySampler-sampler-01082`).
  The allowance is in `tools/smoke_launch.sh` and in the task profile, and is to
  be removed once TinCan picks up the `moth_graphics` with moth_toolkit T-002 in
  it. Nothing else is silenced.

- **A latent null dereference was found and not fixed.**
  `SystemPickup::Update` logs `[error] Unable to locate player` and then
  dereferences a null `playerPosition` in the pickup loop that follows
  (`src/system_pickup.cpp:132`-`152`). It is reachable once the player entity is
  gone. It is outside every task in this session, so it is recorded under
  `## Discovered` in `docs/tasks.md` for planning.

- **`data/behaviour_database.json` was rewritten**, as T-002 says it may be.
  `basic` is now a two-waypoint linear path rather than a `Line`. The map's
  `speed` property, which used to do nothing for `basic`, now applies, so the
  pacing of the star map may have shifted. That is the accepted answer to an open
  question on T-002 and is on the manual list.

- **Everything visual is unverified by the session.** The launch check confirms
  the game starts, plays and shuts down cleanly; it cannot tell whether a wave
  looks like a wave. The manual list below is the real check. Two of the bugs in
  the follow-up above were exactly this kind, and both were found by eye.

- **The entry rule feature (`d6965d5`) is not in `docs/tasks.md`.** It changes
  the behaviour data format by adding an `entry` field to a path state. Worth
  deciding at the next planning pass whether it should be recorded there, since
  nothing else describes it apart from this log and the commit.

## Assumptions

Each task's `Notes` in `docs/tasks.md` carries its assumptions in full. The ones
that shape the result:

- **T-001:** the Spawn button is disabled when the behaviour has no states or any
  state is unfinished; the warning names a behaviour by state index and label,
  because `BehaviourData` carries no name.
- **T-004:** Spawn is also disabled until an enemy is chosen.
- **T-002:** `basic` becomes `[0,0]` to `[0,1200]` at speed 100, which is the
  motion the old `Line` velocity gave.
- **T-003:** `Phase` offsets by its `cycles` times the entity's place in its
  spawn formation, which is the only way entities sharing a behaviour can differ.
  A modifier still set to `Undefined` makes its state incomplete.
- **T-005:** one state at a time is edited in the view, chosen with an "Edit in
  view" radio button; a spawn-relative path is drawn around the editor's spawn
  position.
- **T-006:** the database path is a constant in the editor; a saved behaviour is
  picked up on the next run, not in the running game.
- **T-007:** time markers are ticks across the path rather than numbers, because
  the editor draws into the world surface where it has no font.
